我已经检查了 `results.zip` 里的 `matrix_s01_s08` 测试结果。整体结论：

**测试流程基本跑通，32组全部 passed，没有数据完整性错误；但是部分性能结果明显存在异常，不能直接作为最终 Benchmark 结果提交。**

主要问题集中在：

1. **高负载场景出现大量丢包/延迟爆炸**
2. **部分吞吐量与理论值不匹配**
3. **CPU占用出现超过100%的情况，需要确认统计口径**
4. **正式测试次数不足（全部 repeat=1）**
5. **部分场景设计导致测试结果不可解释**

下面详细分析。

# 9. CPU数据问题

例如：

S05_G4:

```
cpu:
367%
```

Windows psutil统计：

可能是：

多核累计CPU。

例如：

400%

≈

4个核心满载。

所以不能直接写：

CPU占用367%。

Benchmark报告应该转换：

```
CPU utilization (% of total cores)
```

或者：

```
CPU cores used
```

否则容易误解。

尤其：

```yaml
history_depth:
  1000+

  enabled
```

## 必须修改3：区分Python瓶颈

现在测量链：

```
Python
 |
FastDDS Python binding
 |
Fast DDS C++
 |
UDP
```

不是纯：

```
Fast DDS C++
 |
UDP
```

所以报告中应该注明：

> Measurement engine based on Fast DDS Python binding

---

## 必须修改4：重新跑关键场景

不用全部32组重新跑。

优先：

* S01_G4
* S03全部
* S04_G3/G4
* S08_G2/G4

---

最终判断：

**低负载(S01 100~1000Hz、S02、S06)数据可信；高负载(S01 2000Hz、S03、S04、S08)主要反映测试程序/队列瓶颈，不代表 Fast DDS真实能力。**

如果这是为了你之前的 **DDS四中间件横向Benchmark提交**，建议不要直接拿这份矩阵做最终排名，需要先修正压力场景，否则 Fast DDS 会被人为低估。
