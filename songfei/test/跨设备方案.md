# 跨设备（同一 WiFi）三中间件性能对比实验方案

对象：**VSOA / MQTT / Zenoh**；拓扑：发布端在 A 机、订阅端在 B 机
本文只定义**测试场景**与**指标定义**，代码调整由实现方自行处理。

---

## 一、测试场景

命名 `CD1–CD4`，覆盖「速率极限 → 载荷极限 → 拓扑成本 → 极限维持」四个正交压力方向。

### CD1 速率饱和扫描

| 项 | 值 |
|---|---|
| 影响因子 | `publish_rate_hz` |
| 拓扑 | 1 发布端@A → 1 订阅端@B |
| payload | 1 KiB |
| 阶梯 | 100 / 500 / 1000 / 2000 / 5000 / 10000 Hz（6 档） |
| 每档时长 | 20 s |

压"次数"方向：达成吞吐在某一档开始脱离理想线，即该家开始饱和。

### CD2 载荷饱和扫描

| 项 | 值 |
|---|---|
| 影响因子 | `payload_size_bytes` |
| 拓扑 | 1 发布端@A → 1 订阅端@B |
| 速率 | 200 Hz |
| 阶梯 | 1 / 16 / 64 / 256 / 1024 KiB（5 档） |
| 每档时长 | 20 s |

压"字节"方向：达成吞吐撞到 WiFi 物理上限后压平，平台值即带宽饱和点。

### CD3 拓扑扇出

| 项 | 值 |
|---|---|
| 影响因子 | `subscriber_count` |
| 拓扑 | 1 发布端@A → N 订阅端@B，N = 1 / 2 / 4（3 档） |
| 参数 | 1000 Hz / 1 KiB |
| 每档时长 | 20 s |

体现中心化转发与直连的成本结构差异：单订阅者达成率随 N 的增长是否保持。

### CD4 极限维持

| 项 | 值 |
|---|---|
| 影响因子 | 时间（在极限附近持续） |
| 拓扑 | 同 CD1 |
| 档位 | `0.9 × R_sat` 与 `1.2 × R_sat` 两档（由 CD1 结果反推，`R_sat` 见下表判定） |
| 每档时长 | 300 s，每 10 s 一桶（30 桶） |

体现"极限"能否长期保持：分桶看达成率、p95、内存是否随时间下滑。

### 场景总览

| ID | 名称 | 影响因子 | 档数 | 单档时长 |
|---|---|---|---|---|
| CD1 | 速率饱和扫描 | 速率 | 6 | 20 s |
| CD2 | 载荷饱和扫描 | payload | 5 | 20 s |
| CD3 | 拓扑扇出 | 订阅者数 | 3 | 20 s |
| CD4 | 极限维持 | 时间 | 2 | 300 s |

### 极限判定规则

| 判定量 | 定义 |
|---|---|
| 速率饱和点 `R_sat` | `achievement_ratio` 首次 < 99% 且其后各档均 < 99% 的最小档位 |
| 可持续极限速率 | `R_sat` 的前一档 |
| 延迟拐点 `R_knee` | p95 首次超过各档最小 p95 的 3 倍的档位 |
| 带宽饱和点 `B_sat` | 达成吞吐相邻两档增幅 < 5% 且平台平均丢包 > 1% 时的平台值 |
| 极限维持时长 `T_hold` | `0.9 × R_sat` 下 `achievement_ratio ≥ 99%` 的最长连续时长 |
| 退化斜率 | CD4 后 1/3 桶达成率均值 − 前 1/3 桶达成率均值 |

门限（99%、3 倍、5%、1%）为预设值，开测后不得中途调整。某档 CPU 已 > 85% 时该档标记**设备受限**，不参与 `R_sat` 判定。

## 二、指标定义

三家统一走仓库既有口径 `mqtt/mqtt_metrics.py`（Unified metric definitions 1.0），跨设备只补 U-9、U-12 两个派生项。

### 符号

| 符号 | 含义 |
|---|---|
| `S` | payload 字节数（应用层净荷，不含协议头） |
| `N_sent` | 发布端成功发出的条数 |
| `N_recv_win` | 测量窗口内订阅端去重后收到的条数 |
| `P` | 订阅者实例数 |
| `E` | 应交付总数 = `N_sent × P` |
| `T_send` | 发送窗口 = 末次发送 − 首次发送 |
| `T_delivery` | 交付窗口 = 末次接收 − 首次发送 |
| `d_i` | 第 i 条消息的单程延迟（ms） |

### 公式

| # | 指标 | 公式 | 说明 |
|---|---|---|---|
| U-1 | 单程延迟 | `d_i = (a_i − s_i) / 1e6` | `a_i`、`s_i` 须已校正到公共时基 |
| U-2 | 平均延迟 `latency_ms` | `mean(d)` | 算术平均 |
| U-3 | 分位数 `p50/p95/p99` | `h = (n−1)·k`，`x[lo] + (x[hi]−x[lo])·(h−lo)` | 先排序，线性插值 |
| U-4 | 标准差 `latency_std_ms` | `pstdev(d)` | 总体标准差，ddof=0 |
| U-5 | 抖动 `jitter_ms` | `mean(|d_i − d_{i−1}|)` | 仅取序号连续的相邻样本对 |
| U-6 | 达成吞吐 `throughput_mbps` | `N_recv_win × S × 8 / T_delivery / 1e6` | 十进制 1e6 |
| U-7 | 应发吞吐 `offered_throughput_mbps` | `N_sent × S × 8 / T_send / 1e6` | |
| U-8 | 丢包率 `packet_loss` | `(E − N_recv_win) / E` | 分母是 `E`，不是 `N_sent` |
| U-9 | 达成率 `achievement_ratio` | `throughput_mbps / offered_throughput_mbps` | 饱和判定主指标 |
| U-10 | CPU `cpu_percent` | 按采样区间重叠加权平均 | 满一个核 = 100% |
| U-11 | 内存 `memory_mb` | 窗口内 RSS 峰值 | |
| U-12 | 跨设备资源 | 各机逐机记录后求和，`_A`/`_B` 分列 + `total` | 用于定位瓶颈在哪台机器 |
| U-13 | 时钟不确定度 `clock_uncertainty_ms` | `min_RTT / 2` | 取 RTT 最小的那次观测 |

### 统一约束

1. 吞吐一律以**净荷**计，不含协议头、不折算重传。
2. 一律用 `1e6`（十进制），不用 `1024²`。
3. `warmup` 不计入统计；`drain` 单独用于收尾在途消息，不计入统计也不计入丢包。
4. 一律取**去重后**的接收数（`unique_deliveries`），不用含重复的原始计数。
5. `repeats = 5`，报中位数并给出极差；单次结果不作结论。
6. **时基**：跨设备必须先做时钟偏移标定（最小 RTT 法），且每次 run 前重新标定，不可跨 run 复用。延迟样本有效性判据 `clock_uncertainty_ms ≤ 1`，超限则该 run 的延迟类指标标 `unmeasurable`，不参与 U-2 ~ U-5；吞吐与丢包类指标不受此限。
